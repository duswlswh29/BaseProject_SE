Actor / SceneGraph 개발 지침

1. 기본 원칙
화면에 배치하는 월드 오브젝트는 SceneGraph.Create()로 Actor를 생성한다.
Actor는 위치, 회전(도), 크기, 로컬 경계 상자, 활성 상태, 렌더 패스,
외형 설정과 그리기 콜백을 관리한다. 눈, 팔다리, 창문 같은 모델 부품은
해당 Actor 내부에서 그린다. 현재 HUD는 레벨별 하나의 복합 UI Actor다.
튜토리얼과 레벨 1 모두 이 구조를 사용한다.

2. 계층과 수명
SceneGraph가 Actor를 소유하며 게임 코드는 ActorId로 참조한다.
부모의 위치/회전/크기는 자식에게 전파된다. 변환 순서는 T * Rz * Ry * Rx * S다.
Reparent는 로컬 변환을 유지한다. 부모 변경 시 월드 위치가 달라질 수 있다.
순환 계층과 잘못된 부모는 거부한다. Remove는 자식까지 제거한다.
Clear 후에도 ID를 재사용하지 않는다. Find 결과는 사용 전에 확인한다.
삭제된 Actor의 포인터나 참조를 보관하지 않는다.

3. 현재 구성
장면 루트
  레벨
    정적 지형 / 청크 / 나무, 바위, 수면 등의 Actor
    동적 오브젝트 / 플레이어, 적, 전리품, 투사체 등의 Actor
    야영지 / 장작, 불꽃 등의 Actor
  UI

레벨 1은 8 x 8 타일 청크, 튜토리얼은 8 단위 공간 구역으로 정적 물체를 묶는다.
게임 상태와 충돌은 기존 게임 로직이 관리하며 SyncScene에서 Actor에 반영한다.
게임 위치를 바꾸려면 게임 상태도 함께 갱신한다. Actor 변환만 바꾸는 것으로
충돌 지도나 AI 위치가 자동 변경되지는 않는다.

4. 컬링과 최적화
현재 OpenGL 투영/뷰 행렬에서 프러스텀 6개 평면을 추출한다.
Actor의 로컬 AABB를 월드로 변환하고 자식 경계를 합쳐 서브트리 경계를 만든다.
시야 밖 서브트리는 순회를 생략한다. 카메라, 그림자, UI 패스는 따로 판단한다.
카메라 밖 물체도 광원 시야에 있으면 그림자 패스에 포함될 수 있다.
화면 밖이라는 이유로 AI, 전투, 경험치 등 게임 업데이트를 중지하지 않는다.
변환/경계는 변경된 가지에서만 재계산한다.
불투명 물체는 머티리얼/이펙트/메시 키 순으로 정렬한다.
가산 합성 이펙트는 뒤에 그리며 깊이 기록을 끈다.
자동 인스턴싱, 드로 콜 병합, 가림 컬링, LOD는 아직 구현하지 않았다.
WasVisible은 마지막 해당 패스의 결과이며 LastStatistics로 제출/제외 수를 본다.

5. 새 오브젝트 추가
Create(name, parentId)로 만든 뒤 SetTransform, SetBounds, SetPasses,
SetAppearance, SetDraw를 설정한다. 빈 그룹에는 그리기 콜백이 필요 없다.
그리는 Actor에는 반드시 모델 전체를 포함하는 로컬 경계를 지정한다.
애니메이션과 셰이더 변형의 최대 범위도 경계에 포함한다.
ModelCache.Bounds()는 생성 또는 디스크 로딩한 정점으로 계산한 경계를 제공한다.
모델 캐시 파일 형식은 기존과 동일하다.
콜백은 로컬 좌표로 그린다. SceneGraph가 월드 행렬을 적용한다.
콜백 실행 중 Actor 생성/삭제/재부모화 등 그래프 구조를 변경하지 않는다.
게임 배열 원소의 참조를 콜백에 저장하지 않는다. 재할당으로 무효화될 수 있다.
WorldMatrix/WorldBounds를 읽기 전 UpdateTransforms를 호출한다.
Draw는 변환 갱신을 자동 수행한다.

6. 렌더 순서
SyncScene -> BeginShadow / Draw(Shadow)
          -> BeginScene / Draw(World) -> EndScene
          -> BeginUI / Draw(UI) -> SwapBuffers

7. 확인 사항
빌드와 실제 화면 확인은 사용자 담당 원칙을 유지한다.
두 레벨에서 화면 가장자리 물체/그림자가 갑자기 사라지지 않는지 확인한다.
이동, 적 처치, 아이템 획득, 투사체 소멸 및 맵 재생성을 확인한다.
튜토리얼 단계 전환, 안내 표시, 동물, 물/불 효과와 HUD를 확인한다.
